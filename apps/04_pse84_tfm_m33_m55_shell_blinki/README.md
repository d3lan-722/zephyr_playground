# PSE84 TF-M dual-core blinky

Two standalone Zephyr applications that run side by side on the
`kit_pse84_eval` (PSE846GPS2DBZC4A) in the TF-M paired-build
configuration described in the Zephyr board docs:

<https://docs.zephyrproject.org/latest/boards/infineon/kit_pse84_eval/doc/index.html#tf-m-multicore-support>

| App        | Core              | LED            | Behaviour        |
| ---------- | ----------------- | -------------- | ---------------- |
| `cm33_ns/` | Cortex-M33, NS    | `led0` (red)   | shell-controlled |
| `cm55/`    | Cortex-M55        | `led1` (green) | 2 Hz blink       |

Both images set `CONFIG_PSOC_EDGE_M55_SRF_SUPPORT=y` in their
`prj.conf`. This enables the mailbox/relay glue so the CM55
non-secure image can reach the same TF-M Secure Processing
Environment that the CM33-NS image already talks to locally.

> Note: in this multicore mode the CM55 image is **not** built with
> `--sysbuild`. Both images are standalone Zephyr apps; they are
> coordinated through the `PSE84_CM33_BUILD_DIR` CMake variable and
> are flashed independently.

## Architecture

Two independent Zephyr apps share the board. The CM33 secure side
runs TF-M; both non-secure apps use it as their PSA/SPE backend.

```
+-----------------------------+       +-----------------------------+
|  CM33 non-secure (this app) |       |  CM55                       |
|  ------------------------   |       |  ------------------------   |
|  Zephyr kernel              |       |  Zephyr kernel              |
|  Shell on KitProg3 UART     |       |  Blinky task (2 Hz)         |
|      |                      |       |      |                      |
|      v                      |       |      v                      |
|  GPIO led0 (red)            |       |  GPIO led1 (green)          |
|                             |       |                             |
|  PSA / TF-M NS client ------+---+---+------ PSA / TF-M NS client  |
+-----------------------------+   |   +-----------------------------+
                                  v
                     +-----------------------------+
                     |  CM33 secure  (TF-M SPE)    |
                     +-----------------------------+
```

The CM55 reaches the SPE indirectly through the CM33 mailbox/relay,
which is what `CONFIG_PSOC_EDGE_M55_SRF_SUPPORT=y` enables in both
`prj.conf` files.

### CM33-NS runtime

* `main()` runs once at startup: prints a banner, configures `led0`
  inactive, then returns. It does **not** loop.
* `CONFIG_SHELL=y` in `cm33_ns/prj.conf` creates a shell thread that
  reads the KitProg3 UART, tokenises input, and dispatches lines
  starting with `led` to the registered subcommand handlers.
* `cmd_led_on` / `cmd_led_off` are plain synchronous GPIO writes.
  There are no timers, work queues or background threads in this app;
  the LED only changes when the user types a command.

### CM55 runtime

* Independent Zephyr instance, own build directory, own flash.
* Simple periodic blink loop on `led1` — no shell.
* Any PSA call goes through the mailbox relay to the CM33 SPE.

## Prerequisites

* `BOOT SW` on the board set to `ON` (boot from external flash).
* Infineon OpenOCD available to `west flash`. If not already
  configured, point west at it once:

  ```bash
  west config build.cmake-args -- "-DOPENOCD=/usr/local/openocd/bin/openocd"
  ```

* The Zephyr workspace must contain the `trusted-firmware-m`,
  `tf-m-tests` and `tf-psa-crypto` modules (already enabled in this
  repository's `.devcontainer/west.yml`).

## Quick start

A small helper script wraps the per-app build/flash invocations in
the correct order. Run it from this directory:

```bash
./run.sh all      # build + flash
./run.sh build
./run.sh flash
./run.sh clean    # remove build directories
```

## Manual build

Order matters: the CM55 build consumes PSA headers generated by the
CM33-NS TF-M build, so the CM33-NS image is built first.

### 1. CM33 non-secure (TF-M)

```bash
cd cm33_ns
west build -p always -b kit_pse84_eval/pse846gps2dbzc4a/m33/ns
```

Output of interest: `build/zephyr/tfm_merged.hex`.

### 2. CM55

Pass the absolute path of the CM33-NS build directory to the CM55
build via `PSE84_CM33_BUILD_DIR`:

```bash
cd cm55
west build -p always -b kit_pse84_eval/pse846gps2dbzc4a/m55 -- \
    -DPSE84_CM33_BUILD_DIR=$(realpath ../cm33_ns/build)
```

Output of interest: `build/zephyr/zephyr.hex`.

## Manual flash

The CM33-NS image jumps to the CM55 image on boot, so the CM55
image must be present first.

```bash
# from this directory
west flash -d cm55/build
west flash -d cm33_ns/build
```

After reset the green LED (CM55) blinks at 2 Hz and the red LED
(CM33-NS) is off. Open the KitProg3 UART at 115200 8N1 to get the
`uart:~$` prompt and try:

```
led on
led off
```

## Console

The KitProg3 USB-UART bridge exposes the CM33-NS console at 115200
8N1, and the Zephyr shell (`CONFIG_SHELL=y`) is bound to it. Type
`help` at the `uart:~$` prompt to list all built-in commands; the
LED commands live under `led`. The CM55 image has no UART of its
own in this configuration; its `printk`/`printf` output is not
visible on the console.

## Clean

```bash
./run.sh clean
# or manually
rm -rf cm33_ns/build cm55/build
```
